# fan-dvizhok — нативный движок ФАН (Android / iOS / Windows)

Слово владельца 2026-09-28: «не для продажи, для внутреннего пользования; нативные приложения-движки для работы с CRM
в режиме только сервера: вместо браузера — продвинутый нативный движок, чтобы подключаться к камере и управлять
нативными инструментами устройства».

Движок = нативное приложение с одним WebView, в котором живёт CRM платформы ФАН (Hub2). Своего содержимого нет —
всё с сервера. Движок добавляет: камеру и сканер, push и системные уведомления, печать на сетевые принтеры, буфер,
вибрацию, файлы, «не гасить экран», а на Windows ещё Web Serial / USB / Bluetooth без диалогов (весы, сканеры).
Законы платформы сохраняются: CRM = оболочка, приложения внутри рамки, права в ядре CRM, своих юзеров и токенов нет.

**Контракт (закон для всех трёх платформ):** [docs/SPEC-FANDEVICE-v1.md](docs/SPEC-FANDEVICE-v1.md).

## Как это устроено — один механизм

```
страница CRM / приложение в рамке crm_embed
   │ window.FanDevice.camera.scan() · .print.tcp() · .notify.show() · .has('…') · .on('push', …)
   ▼
web/fan-device.js — ОДИН файл, движок вживляет его в верхнюю страницу; в same-origin рамки кладётся тот же объект
   │ FanNative.call(json) → строка JSON | pending ; ответы и события → FanDevice._deliver(json)
   ▼
desktop/main.js (Electron)  ·  mobile/android (Kotlin, addJavascriptInterface)  ·  mobile/ios (Swift, WKScriptMessageHandler)
```

Почему не Capacitor: его мост на страницах с чужого сервера инжектится ненадёжно (Android с `*` в allowNavigation
не инжектит, POST-переходы теряют плагины, `server.url` «не для production» по документации). Свой мост — 2 функции,
одинаковые везде, и полный контроль над cookie, разрешениями и рамками.

## Что где

| папка | что | собирается сейчас |
|---|---|---|
| `web/fan-device.js` | общий JS-слой (ООП: FanDevice, транспорты, WebFallback, Bytes) | — |
| `tests/` | 14 unit-тестов shim (`npm test`) + `fixtures/selftest.html` — страница самопроверки для любого движка | ✓ |
| `desktop/` | Windows: Electron 44. `main.js` (Engine, CommandRouter, Permissions, TcpPrinter, Settings), `preload.js` (транспорт + сканер-клавиатура), `ui/settings.html`, `ui/offline.html` | ✓ `npm run selftest:win` → код 0 + `desktop/selftest.png` |
| `mobile/android/` | Kotlin: `MainActivity` (WebView, разрешения, вживление), `FanBridge`, `Commands` (сканер Google, фото, FCM, TCP-печать, файлы), `Notifier`, `SettingsActivity` (адрес + QR) | нужен Android SDK — `scripts/setup-android-sdk.ps1` |
| `mobile/ios/` | Swift: `EngineViewController` (WKWebView, мост, разрешения), `Commands` (Vision-сканер, фото, APNs, Network-печать), `SettingsViewController`; проект через XcodeGen `project.yml` | нужен Mac + Apple ID |

Shim не копируется: Android берёт `../../../web` как assets, iOS — ресурс из `project.yml`, Electron читает файл.

## Запуск и проверка

```powershell
npm test                    # shim
npm run selftest:win        # Electron открывает tests/fixtures/selftest.html, ждёт FAN-SELFTEST-OK, снимает selftest.png
npm run start:win           # обычный запуск: первый раз — окно настроек (адрес сервера), потом CRM
```

Android (один раз, ~1 ГБ загрузок, спросить владельца): `powershell -ExecutionPolicy Bypass -File scripts\setup-android-sdk.ps1`,
затем `cd mobile\android; .\gradlew.bat assembleDebug` → `app\build\outputs\apk\debug\app-debug.apk`, ставим на телефон
руками (внутреннее использование, магазин не нужен). Push: положить `google-services.json` из консоли Firebase в
`mobile/android/app/` — FCM включится сам (`BuildConfig.HAS_FIREBASE`); без файла `push.register` → `none`.

iOS: на Mac `xcodegen generate`, открыть `FanDvizhok.xcodeproj`, подписать своим Apple ID, Run на iPhone.
Без аккаунта Apple Developer установка на устройство действует 7 дней (бесплатный профиль), push APNs — только с платным.

## Адрес сервера

Публичный адрес CRM меняется с перезапуском туннеля, поэтому в код не зашит: экран настроек движка (первый запуск,
ошибка загрузки, команда `settings.open`), руками или QR с адресом. Разрешения (камера, микрофон, геолокация,
уведомления) выдаются только этому origin, `FanNative` чужому origin отвечает `denied`.

## Как приложению CRM пользоваться движком

```js
const dev = window.FanDevice;                       // в рамке — тот же объект, что у CRM
if (dev && dev.native) await dev.ready;
if (dev?.has('camera.scan')) {                       // в браузере без BarcodeDetector — false
  const { text } = await dev.camera.scan({ formats: ['ean13', 'qr'] });
}
await dev.print.tcp({ host: '192.168.88.50', bytes: tsplBytes });   // ценники TSC без демона печати
dev.on('push.open', ({ url }) => { /* движок уже перешёл на url */ });
```

Без движка (обычный браузер) объекта `FanDevice` нет вовсе — приложение работает как раньше.
